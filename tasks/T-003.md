# T-003: Redirect and hit counting

Status: in_review
Depends on: T-002

## Goal
Visiting `/<code>` redirects to the original URL, and each successful redirect is counted and visible on the link.

## Scope
In:
- `LinkRepository.increment_hits(code)` on the protocol and the in-memory implementation.
- `GET /{code}` -> 302 with `Location`, registered after the fixed routes.
- `GET /links/{code}` (auth) returning `LinkOut` with the live `hit_count`.
Out:
- Expiry and 410 responses - T-004.
- Listing - T-005.
- HEAD support, favicon handling, counting anything other than 302s.

## Interface (copied from docs/SPEC.md so the ticket is self-contained)
- Modules: src/app/repository.py (+increment_hits), src/app/routes/redirect.py, src/app/routes/links.py
  (+GET /links/{code}), src/app/main.py (include redirect router last)

```python
# src/app/repository.py (added to LinkRepository and InMemoryLinkRepository)
def increment_hits(self, code: str) -> None: ...   # atomically +1; raises LinkNotFoundError if unknown
```

- `GET /{code}` (no auth)
  - 302 Found, header `Location: <link.url>` verbatim, empty body. Then `repo.increment_hits(code)`.
  - 404 `{"error": "not_found", "message": "..."}` if no link has that code. Nothing is counted.
  - `/healthz` and `/links` are matched by their own routers first and are never treated as codes.
- `GET /links/{code}` (header `X-API-Key` required)
  - 200: `{"code": ..., "url": ..., "created_at": ..., "expires_at": null, "hit_count": <int>}`
  - 401 `unauthorized`; 404 `not_found`.
- Error envelope and auth behaviour as in T-002.

## Acceptance criteria
AC1. Given a link was created for `https://example.com/x?y=1#z` When `GET /{code}` is requested without any API key and with `follow_redirects=False` Then the response is 302, the `Location` header equals `https://example.com/x?y=1#z` exactly, and the body is empty.
AC2. Given no link with code `zzzzzzz` exists When `GET /zzzzzzz` is requested Then the response is 404 with `error == "not_found"`.
AC3. Given a freshly created link When `GET /links/{code}` is requested with the valid API key Then the response is 200 with the same `code` and `url` as the create response and `hit_count == 0`.
AC4. Given a link that has been redirected 3 times via `GET /{code}` When `GET /links/{code}` is requested Then `hit_count == 3`; and a subsequent 404 request to an unknown code does not change that count.
AC5. Given a link exists When `GET /links/{code}` is requested without the `X-API-Key` header, or for an unknown code with the valid key Then the responses are 401 `unauthorized` and 404 `not_found` respectively.
