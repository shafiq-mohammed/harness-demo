# T-005: List links with paging

Status: todo
Depends on: T-002

## Goal
An engineer with an API key can page through all existing links, so thousands of links can be inspected without one giant response.

## Scope
In:
- `LinkRepository.list(limit, after_code)` on the protocol and the in-memory implementation (keyset by code).
- `LinkPage` schema and `GET /links?limit=&cursor=` with `next_cursor`.
Out:
- Filtering (by URL, by expired state), sorting options, total counts.
- Offset-based paging.
- Any change to create/redirect/expiry behaviour.

## Interface (copied from docs/SPEC.md so the ticket is self-contained)
- Modules: src/app/repository.py (+list), src/app/schemas.py (+LinkPage), src/app/routes/links.py (+GET /links)

```python
# src/app/repository.py (added to LinkRepository and InMemoryLinkRepository)
def list(self, *, limit: int, after_code: str | None = None) -> list[Link]:
    """Up to `limit` links with code > after_code (or from the start), ordered by code ascending."""

# src/app/schemas.py (added)
class LinkPage(BaseModel):
    items: list[LinkOut]
    next_cursor: str | None
```

- `GET /links?limit=20&cursor=<opaque>` (header `X-API-Key` required)
  - Query: `limit` int, `ge=1`, `le=100`, default 20; `cursor` optional string.
  - 200: `{"items": [LinkOut, ...], "next_cursor": "<string or null>"}`
  - `items` ordered by `code` ascending. `next_cursor` is null if and only if no links remain after the
    last item; otherwise pass it back as `cursor` for the next page. Pages never overlap or skip links.
    An unknown cursor value starts after that value (keyset semantics), it is not an error.
  - Implementation hint: `repo.list(limit=limit + 1, after_code=cursor)`; if more than `limit` results,
    truncate and set `next_cursor = items[-1].code`.
  - 401 `unauthorized`; 422 `validation_error` for `limit` outside 1..100 or non-integer.
- `LinkOut`, error envelope and auth as in T-002.

## Acceptance criteria
AC1. Given no links exist When `GET /links` is requested with the valid key Then the response is 200 `{"items": [], "next_cursor": null}`.
AC2. Given 5 links exist When `GET /links?limit=2` is requested Then the response is 200 with exactly 2 items whose codes are the 2 smallest codes in ascending order, each item having the `LinkOut` shape, and `next_cursor` is a non-empty string.
AC3. Given 5 links exist When pages are fetched with `limit=2`, passing each `next_cursor` back as `cursor` until `next_cursor` is null Then the concatenated codes are exactly the 5 created codes, sorted ascending, with no duplicates, and the last page has `next_cursor == null`.
AC4. Given 3 links exist When `GET /links?limit=3` and `GET /links` (default limit) are requested Then both return all 3 items and `next_cursor` is null.
AC5. Given the valid key When `GET /links?limit=0`, `GET /links?limit=101` and `GET /links?limit=abc` are requested Then each response is 422 with `error == "validation_error"`; and `GET /links` without the header is 401 `unauthorized`.
