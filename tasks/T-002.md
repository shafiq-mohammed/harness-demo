# T-002: Create a short link

Status: in_progress
Depends on: T-001

## Goal
An engineer with an API key can POST a long http(s) URL and get back a short code.

## Scope
In:
- `X-API-Key` auth dependency `require_api_key`.
- `Link` model, `LinkRepository` protocol (add, get) and `InMemoryLinkRepository`.
- `create_app` gains a `repo` parameter stored on `app.state.repo`.
- `generate_code()` and `POST /links` returning `LinkOut`.
- `tests/conftest.py` gains `API_KEY`, `HEADERS`, the `repo` fixture, and passes the key and repo to `client`.
Out:
- Redirecting (`GET /{code}`) - T-003.
- Expiry / `expires_at` on the request - T-004.
- Listing links - T-005.
- Persistent storage, custom aliases, `short_url` in the response, Dockerfile.

- Error envelope as in T-001; this ticket adds `unauthorized` 401 and exercises `validation_error` 422.
- `POST /links` (header `X-API-Key` required)
  - Request: `{"url": "https://example.com/some/long/path"}`
  - 201: `{"code": "<7 chars [A-Za-z0-9]>", "url": "<verbatim>", "created_at": "<clock.now() ISO>", "expires_at": null, "hit_count": 0}`
  - 401 `unauthorized` when header missing, key unknown, or no keys configured.
  - 422 `validation_error` when body is not JSON, `url` missing/empty, scheme not http(s), no host,
    or longer than 2048 chars.
  - Code generation retries `generate_code()` up to 5 times on `CodeAlreadyExistsError`.
- `GET /healthz` unchanged and still requires no key.

## Acceptance criteria
AC1. Given the app is built with API key `test-key` and a FixedClock at T0 When `POST /links` is sent with header `X-API-Key: test-key` and body `{"url": "https://example.com/a/b?c=1"}` Then the response is 201 with `url` equal to the input verbatim, `code` matching `^[A-Za-z0-9]{7}$`, `created_at` equal to T0, `expires_at` null and `hit_count` 0.
AC2. Given a valid body When `POST /links` is sent with no `X-API-Key` header, or with `X-API-Key: wrong` Then the response is 401 with body `{"error": "unauthorized", "message": <non-empty string>}`.
AC3. Given the valid API key When `POST /links` is sent with `{"url": "ftp://example.com"}`, `{"url": "not a url"}`, `{"url": "http://"}`, `{"url": ""}`, `{}` or a URL of 2049 characters Then each response is 422 with `error == "validation_error"` and a `details` list, never a 500.
AC4. Given the valid API key When two links are created for the same URL Then both are 201 and their `code` values differ.
AC5. Given an app built with `Settings()` (no keys configured) When `POST /links` is sent with `X-API-Key: test-key` and a valid body Then the response is 401 `unauthorized`.

- AC3: parametrize over the invalid inputs; edge: exactly 2048 chars is accepted (201); error path: a
  non-JSON body (`content="not json"`, JSON content type) is 422, not 500.

- AC5: build a second app in the test with `Settings()`; edge: `GET /healthz` on that app is still 200.
